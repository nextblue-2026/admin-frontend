# 한끗 운영 콘솔

읽기 전용 P0 관리자 화면입니다. 기존 Spring Boot API를 `/api/v1` 경로로 사용합니다.

## 로컬 실행

1. 이 폴더에서 `npm ci` 후 `npm run dev`를 실행합니다.
2. 브라우저에서 `http://localhost:5173`에 접속합니다. 개발 서버의 `/api` 요청은 운영 API(`https://api.hankkt.site`)로 전달됩니다. 실제 운영 데이터와 SMS가 사용되므로 테스트 요청에 주의하세요.

운영자 등록 화면은 없습니다. 기존 전화번호 인증 회원 계정을 만든 뒤 서버의 `ADMIN_MEMBER_IDS` 환경 변수에 **회원 UUID**를 쉼표로 구분해 넣어야 합니다. App Store 심사용 계정은 허용 목록에서 제외합니다. 기본값은 빈 목록이며 이때 관리자 API는 전부 403을 반환합니다. 전화번호나 인증번호를 저장소에 기록하지 마세요. 관리자 앱에서 기존 SMS 인증으로 로그인하고, 서버가 유효한 회원 세션과 UUID 허용 목록을 모두 확인합니다.

## 제공 기능

- 7/30/90일 신규 회원, 매칭, 약속, 신고, 후기와 전체 회원/활성 회원 집계
- 오늘/최근 7일/최근 30일 이용 회원 수. `member_activity_days` 수집 이전 데이터는 소급하지 않음
- 회원 이름·아이디·UUID, 상태, 한국시간 가입일 구간 검색과 최근 30개 주요 활동 조회
- 신고 접수일 구간, 신고자·사유 검색, 상태·대상 유형 필터
- 관리자 감사 로그와 일반 회원 주요 활동 로그 전환, 행위자·검색어·발생일 구간 필터

모든 목록은 서버에서 필터링하고 페이지를 나눠 읽습니다. 일반 회원 로그는 현재 기록 중인 가입·로그인·매칭·약속·거래 완료·후기·신고 등의 주요 이벤트만 보여주며 전체 HTTP 접근 기록은 아닙니다. 신고 본문, 채팅 본문, 전화번호, 좌표는 관리자 응답에 포함하지 않습니다. 회원 제재·신고 조치·데이터 내보내기·민감 채팅 열람·노쇼·실거래액·외부 문의 처리는 P1입니다.

첫 문자 인증 후 관리자 갱신 토큰은 `HttpOnly; Secure; SameSite=Strict` 호스트 전용 쿠키에 저장됩니다. 페이지를 다시 열면 쿠키로 액세스 토큰을 발급받으며, 최초 인증 시점부터 최대 30일 후에는 문자를 다시 인증해야 합니다. 액세스 토큰은 화면 메모리에만 둡니다. 기존 `sessionStorage` 로그인 상태는 삭제하므로 이 변경을 적용한 뒤에는 문자 인증이 한 번 필요합니다. 로그아웃은 서버 세션과 쿠키를 폐기합니다. 여러 탭에서 토큰이 동시에 회전되지 않도록 지원 브라우저에서는 Web Locks를 사용합니다. 백엔드 V32·V33 마이그레이션을 먼저 적용해야 조회 인덱스가 생성됩니다. 운영 배포 전 API 호스트(`vercel.json`)와 관리자 허용 목록을 확인하세요.

문자 인증 요청의 식별값은 해당 브라우저 탭의 `sessionStorage`에 만료 시각까지 보관합니다. 30초 재요청 제한이 발생하면 아직 유효한 동일 번호의 요청이 있는 경우 이전 인증번호 입력 화면으로 돌아갑니다. 인증번호 자체는 저장하지 않으며 인증 성공 또는 만료 시 식별값을 삭제합니다. 이미 사용한 인증번호나 다른 기기에서 받은 문자는 이 화면에서 재사용할 수 없습니다.
